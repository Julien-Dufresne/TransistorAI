# Day 18 — MVP Reliability and Human Evaluation Validation

**Project:** TransistorAI — German-to-English Machine Translation  
**Date:** 9 November 2026  
**Models:** E0 Baseline NMT, E1 Technical NMT, E2 Mixed NMT, E3 Qwen LLM

## 1. Objectives

Day 18 focused on validating the reliability of the TransistorAI MVP before final evaluation and presentation.

The main objectives were to verify participant evaluation persistence, prevent duplicate votes, test inference across all four translation models, and validate the Human Evaluation Analytics dashboard.

## 2. SQLite Persistence and Duplicate Protection

Six automated tests passed.

The tests verified:

- Votes remain stored after reopening a SQLite connection.
- Duplicate votes from the same participant for the same sentence are rejected.
- Different participants can evaluate the same sentence independently.
- Original votes remain unchanged after duplicate attempts.
- Completed evaluation IDs can be recovered.
- Model mappings are preserved when multiple systems produce identical translations.

**Result:** 6/6 tests passed.

All tests used an isolated temporary database. Existing evaluation votes were not modified.

### Translation quality observation

The E3 model produced an incorrect technical translation.

**Source:** Starten Sie den Server neu.  
**E3 output:** Restarten Sie den Server neu.  
**Expected:** Restart the server.

Although E3 completed inference successfully, its output remained partly German.

This demonstrates the distinction between operational reliability and semantic translation quality.

The remaining observed outputs were generally appropriate for their test sentences, including preservation of negation, numerical meaning, and the `{filename}` placeholder.

## 4. Human Evaluation Analytics

The dashboard was reviewed and updated to correctly aggregate model preferences across both evaluation domains.

Two issues were addressed:

1. The overall preference view previously expected an `overall` category that was not generated by the preference analysis.
2. The chart could reference an uninitialized `totals` variable when the selected preference dataset was empty.

The updated dashboard initializes all four model totals and aggregates general and technical votes for the overall view.

Manual validation confirmed that the Overall, General, and Technical selections work.

### Automated analytics tests

Five tests passed, covering:

- Fractional preference totals
- Equal credit for models producing identical selected translations
- Agreement restricted to sentences evaluated by multiple participants
- Domain-specific agreement
- Empty agreement handling

**Result:** 5/5 tests passed.

## 5. Evaluation Methodology and Limitations

The human evaluation pipeline uses anonymized participant IDs, randomized translation presentation, and SQLite vote storage.

Agreement is calculated using exact selected-text matches between participants who evaluated the same sentence.

Model preferences use fractional credit when identical translations are associated with multiple models.

Current pilot votes were submitted for demonstration purposes and should not be interpreted as genuine human preference evidence.

The smoke-test dataset contains only five sentences. Its results demonstrate basic inference functionality, not comprehensive translation quality.

Latency measurements were collected but have not yet been analyzed.
